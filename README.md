# Issue Desk — 분야별 이슈 수집 작업실

Java 17 / Spring Boot 3.5 + React 19 / TypeScript 기반의 로컬 개인용 수집 도구입니다.
분야 생성 → 출처 등록 → 수동/예약 수집 → 자료 검색·검토·보관까지 구현했습니다.
블로그 글 생성, AI 요약, 이미지 생성, 계정 발행은 이번 범위에 포함하지 않습니다.

## 빠른 시작 (Windows PowerShell)

Java 17+, Node.js 22.12+가 필요합니다. Maven은 포함된 Wrapper가 내려받습니다.

```powershell
cd C:\porject\autoBlog
.\scripts\start.ps1
```

- 화면: http://127.0.0.1:5173
- 백엔드 상태: http://127.0.0.1:8080/api/health
- 종료: `.\scripts\stop.ps1`
- 의존성 설치를 이미 했다면 `.\scripts\start.ps1 -SkipInstall`
- 로그: `.tools/backend.log`, `.tools/backend-error.log`, `.tools/frontend.log`
- 로컬 DB: `backend/data/issuedesk.mv.db` (서버 종료 후 백업)

기본값은 파일 기반 H2 DB입니다. 재시작해도 저장된 분야·출처·자료가 유지됩니다.
서버는 loopback에 바인딩됩니다. 이 버전은 인증 없는 **단일 사용자·단일 백엔드 인스턴스**용입니다.
외부 배포나 여러 사용자 지원은 인증·권한, HTTPS, 작업 큐/분산 잠금을 추가한 뒤 진행해야 합니다.

개별 실행:

```powershell
# 터미널 1
cd backend
.\mvnw.cmd spring-boot:run

# 터미널 2
cd frontend
npm ci
npm run dev
```

## 사용 순서

1. **새 분야 만들기**에서 이름·설명·상세 지침을 입력합니다.
2. 포함/제외 키워드와 관리 태그는 Enter 또는 쉼표로 추가합니다.
3. **수집 출처 → 출처 추가**에서 RSS·YouTube·네이버 뉴스/블로그 모듈을 선택합니다.
4. **지금 수집**을 누릅니다. 한 출처가 실패해도 다른 출처는 계속 수집합니다.
5. **수집 결과**에서 제목·매체·출처·기간·상태로 필터링하고 자료를 읽음·보관·숨김 처리합니다.
6. 제목을 클릭하면 설명·발췌문과 원문 링크를 확인할 수 있습니다.
7. **실행 이력**에서 출처별 조회/신규/중복/제외 건수와 실패 이유를 확인합니다.
8. 분야 편집에서 정기 수집을 활성화할 수 있습니다. 서버가 실행 중이어야 합니다.

상세 지침과 관리 태그는 관리용 메타데이터입니다. AI가 지침을 해석해 수집하지 않습니다.
RSS는 포함 키워드 중 하나라도 제목/발췌문에 일치해야 수집하며, 키워드가 없으면 전체 피드 항목을 받습니다.
검색 모듈은 출처의 검색어 또는 분야 키워드로 검색합니다. 모든 모듈에 제외 키워드가 적용됩니다.
언어·지역 설정은 YouTube 검색에만 적용됩니다.

## 모듈과 API 키

`.env.example`을 `.env`로 복사하고 필요한 값만 입력한 뒤 시작 스크립트로 재실행하세요.
`.env`는 Git 제외 대상이며 API 키는 브라우저에 전달하지 않습니다.
수동 실행 시에는 같은 값을 서버 환경 변수로 설정해야 합니다.

| 모듈 | 수집 내용 | 설정 | 한 번의 수집 범위 |
|---|---|---|---|
| RSS / Atom | 제목, 링크, 작성자, 게시일, 제공된 설명 | 공개 피드 URL | 피드 앞쪽 최대 200건 |
| YouTube | 영상 제목, 설명, 채널명, 게시일, 링크 | `YOUTUBE_API_KEY` | 최신 최대 50건 |
| 네이버 뉴스 검색 | 제목, 원문 링크, 게시일, 발췌문 | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 검색어당 최신 최대 100건 |
| 네이버 블로그 검색 | 제목, 작성자, 링크, 게시일, 발췌문 | 위와 동일 | 검색어당 최신 최대 100건 |

- API 키가 없으면 모듈이 **인증 필요**로 표시됩니다. 출처 설정을 미리 저장할 수 있지만 해당 출처 실행은 실패로 기록됩니다.
- 검색 모듈은 최신 결과를 반복 조회하는 방식입니다. 전체 과거 자료 백필이나 모든 신규 게시물의 무누락 수집을 보장하지 않습니다.
- YouTube는 키워드를 OR(`|`)로 조합합니다. 채널 ID로 범위를 제한할 수 있습니다. 자막·영상 다운로드는 구현하지 않습니다.
- 네이버는 키워드별로 조회하고 기본 키워드는 최대 5개입니다. 그 이상이면 출처별 검색어를 지정해야 합니다.
- 원문 페이지 크롤링과 썸네일 다운로드는 하지 않습니다. 결과의 설명은 AI 요약이 아닙니다.
- 수집 출처의 이용 조건을 확인한 자료를 연결하세요.

## 예약 및 중복 처리

- 매일 09:00 / 평일 09:00 / 6시간 간격 프리셋과 Spring 6필드 cron 직접 설정을 제공합니다.
- 시간대는 IANA 식별자를 저장합니다. 최소 수집 간격은 5분이며 스케줄러는 30초마다 확인합니다.
- 화면 시각은 현재 브라우저의 시간대로 표시되고, 게시 기간 필터는 분야의 시간대로 해석합니다.
- 서버 중단 중 놓친 일정은 재시작 후 한 번 실행합니다. 모든 누락 시각을 각각 재현하지 않습니다.
- 수집 중 중복 실행과 분야/출처 삭제를 막습니다. 최대 20개 분야가 대기할 수 있고 실행은 순차적입니다.
- HTTP 통신/서버 일시 오류는 한 번 재시도합니다. 인증/호출 제한(4xx) 오류는 다음 실행까지 재시도하지 않습니다.
- URL의 fragment·대표 추적 파라미터를 제거한 뒤 SHA-256 키로 중복을 확인합니다.
- 같은 자료가 여러 분야에 해당하면 콘텐츠는 하나, 분야 연결은 각각 저장합니다. 읽음/보관 상태는 분야별로 독립적입니다.
- 같은 사건을 다룬 서로 다른 기사 묶기, 원문 수정 감지, 매체 간 내용 기반 중복 판단은 후속 기능입니다.
- 원본 콘텐츠의 제목·매체·출처는 첫 수집 당시 값을 유지합니다. 다른 출처에서 같은 URL을 발견한 경로를 모두 저장하는 provenance 모델은 후속 확장 대상입니다.
- 한 출처의 저장은 트랜잭션으로 처리됩니다. 재시작 당시 대기/진행 상태는 실패로 전환해 다시 실행할 수 있습니다.

## PostgreSQL 사용

Docker Compose는 PostgreSQL 17을 제공합니다. 기존 PostgreSQL 서버를 사용해도 됩니다.

```dotenv
SPRING_PROFILES_ACTIVE=postgres
DB_URL=jdbc:postgresql://localhost:5432/issuedesk
DB_USER=issuedesk
DB_PASSWORD=your-local-password
```

위 값을 `.env`에 설정하고:

```powershell
docker compose up -d
.\scripts\start.ps1
```

Flyway가 스키마를 자동 생성합니다. H2와 PostgreSQL은 별도 데이터 저장소이며 데이터는 자동 복사되지 않습니다.
로컬 PostgreSQL 18.2에서도 동일한 통합 테스트를 검증했습니다. BOM의 Flyway는 17까지 검증된 버전이라는 안내 로그가 나오지만 이번 스키마/쿼리 테스트는 통과했습니다.

## 검증

```powershell
cd backend
.\mvnw.cmd test
cd ..\frontend
npm run build
```

PostgreSQL 통합 테스트는 **폐기 가능한 별도 DB**만 사용하세요. 테스트는 해당 DB의 분야/자료를 초기화합니다.

```powershell
$env:TEST_DB_URL='jdbc:postgresql://127.0.0.1:55432/issuedesk_test'
$env:TEST_DB_USER='issuedesk'
$env:TEST_DB_PASSWORD='test-password'
cd backend
.\mvnw.cmd test
```

자동 테스트는 RSS/Atom 파싱, XML 외부 엔티티 차단, URL 정규화, 비공개 네트워크 주소 차단,
실제 HTTP API CRUD, 중복/제외 처리, 분야 간 공유, 상태 변경 트랜잭션, 필터,
중복 실행 방지, 출처별 부분 실패, 예약 실행을 검증합니다. 외부 API 응답은 테스트에서 fixture로 대체합니다.

새 수집 모듈은 `Collector` 구현을 Spring Bean으로 등록하고 `SourceInput`의 모듈 검증 및 화면 입력 필드를 확장합니다.
기존 모듈에 출처를 추가하는 작업은 코드 변경 없이 화면에서 가능합니다.

API 목록은 [docs/api.md](docs/api.md)를 참고하세요.

## 선택한 자료의 AI 분석

수집 결과에서 기간·출처·검색어로 범위를 좁힌 후 체크박스로 자료를 선택하고 **선택 자료 분석**을 누릅니다. 간단 분석은 최대 20건(자료당 발췌 600자), 상세 분석은 최대 10건(자료당 2,000자)입니다. 전체 입력은 각각 24,000자·40,000자로 제한됩니다. 실행 전 범위 확인은 AI를 호출하지 않습니다.

분석된 소재 탭에는 같은 이슈를 묶은 한국어 요약이 표시됩니다. 상세에서는 추천 카테고리와 이유, 독자층, 글의 방향, 제목 후보, 목차, 핵심 내용, 확인할 사항과 원문 출처를 확인할 수 있습니다. 현재 수집기에 저장된 제목·설명·발췌를 분석하므로 기사 전문이나 영상 자막을 모두 읽은 결과는 아닙니다.

분석은 로컬 Codex CLI의 **ChatGPT 구독 로그인**으로 실행합니다. OpenAI API 키를 요구하거나 API 과금 방식으로 전환하지 않습니다. 프로젝트 전용 CLI는 시작 스크립트에서 설치합니다. 필요하면 `analysis-runtime` 폴더에서 `npx codex login`으로 로그인하세요. 이 방식은 서버가 실행되는 PC의 로그인과 인터넷 연결이 필요하며, 불특정 다수에게 제공하는 공용 분석 서비스용으로 구성된 것은 아닙니다.

예약 분석은 없고, 사용자가 실행한 선택 범위만 전송합니다. 동시 분석은 1개이며 같은 입력·지시의 성공 결과는 재사용합니다. 실패·한도 초과 시 앱은 자동 재시도하지 않습니다. 중단 버튼으로 실행을 종료할 수 있으나 이미 사용한 토큰은 되돌아오지 않습니다. 분석은 구독 사용량을 소비하며, 별도로 구매한 추가 크레딧 사용 여부는 계정 설정에 따릅니다. 입력 글자 수는 토큰 수가 아니며 지침·출력도 사용량에 포함됩니다. 완료 후 CLI가 보고한 입력·출력·캐시 토큰을 표시합니다.

일반 `mvnw test`는 외부 AI 호출 없이 선택 범위, 출처 검증, 결과 재사용, 실패와 취소를 검사합니다. `ISSUE_DESK_CODEX_SMOKE=true`와 `-Dtest=CodexAnalysisSmokeTest`를 명시한 실제 연결 테스트는 작은 가상 자료로 구독 사용량을 소비합니다.

## 티스토리 글 작성

분석된 소재 → 블로그 기획 상세 → **이 소재로 블로그 글 작성**에서 디렉션을 입력합니다. 선택한 소재의 원문만 최대 5개, 각 8,000자까지 공개 HTML의 article/main 요소에서 추출합니다. 접근 불가·유튜브는 기존 발췌문을 사용하고 자료별 한계를 표시합니다. 로그인/유료 원문이나 영상 자막을 우회 수집하지 않습니다.

작성은 기존 ChatGPT 구독 CLI를 사용합니다. 제목·본문 HTML·카테고리·태그를 수정하고 미리보기를 확인한 뒤, `https://이름.tistory.com` 주소를 입력하여 비공개 작성을 실행합니다. 본문 하단 출처 링크는 앱이 직접 붙입니다. 원본 이미지를 자동 복제하지 않습니다.

티스토리 연결은 Windows에 설치된 Microsoft Edge와 프로젝트 전용 Playwright를 사용합니다. 최초 실행 시 표시되는 Edge 창에서 직접 로그인합니다. 세션은 `.tools/tistory-profile`에 로컬 저장되고, 비밀번호나 세션 쿠키를 앱 DB나 AI로 보내지 않습니다. 같은 이름의 카테고리가 없거나 태그 입력란을 찾지 못하면 티스토리에서 직접 확인해야 합니다. 편집기 내용이 이미 있으면 덮어쓰지 않습니다.

비공개 선택 확인 → 비공개 저장 버튼 → 글 목록의 제목·비공개 상태 확인까지 성공해야 저장 완료로 표시합니다. 다른 화면이거나 결과를 확인할 수 없으면 브라우저를 열어 둔 채 확인 필요 상태로 끝납니다. 불확실한 전송은 재시도하지 않습니다. 확인 후 사용자가 브라우저 창을 닫아야 다음 연결에서 프로필을 사용할 수 있습니다. 공개 발행은 티스토리에서 직접 검수 후 진행합니다.

**검증 범위:** 원문 선택·HTML 정리·초안 저장·중복 전송 방지는 자동 테스트로 검증합니다. 브라우저 모듈의 비공개 확인 실패 시 중단도 테스트합니다. 실제 계정의 편집기 및 비공개 저장 호환성은 해당 블로그 로그인 후 별도 실사용 검증이 필요합니다. 공식 발행 API가 없는 화면 연동이므로 티스토리 편집기 변경 시 수정이 필요할 수 있습니다.
