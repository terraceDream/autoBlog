# 자동 편집 작업실 개선 계획

## 목표와 기본 독자
사이트 목록 관리와 수백 건의 자료 선택을 사용자가 반복하지 않도록 한다. 기본 독자는 AI를 업무에 활용하려는 실무자이며 분야별로 변경할 수 있다. 공개 발행은 기존 검수 흐름을 유지한다.

## 반복 1: 발견 → 추천 → 작성의 연결
1. 키워드 기반 검색 출처를 자동 등록한다. 기술 커뮤니티의 외부 원문과 실제 추천·댓글 신호를 수집하고, API 키가 있는 YouTube·네이버 검색을 연결한다. 중복 등록하지 않고 기존 수동 출처는 보존한다.
2. 추천 작업실을 기본 진입점으로 둔다. 최근 자료의 시의성·분야 관련성·설명 근거·관심 신호로 후보를 줄이고 출처 편중을 제한한다. 전체 검토 범위와 제외 이유를 공개한다.
3. AI가 후보를 같은 사건 단위로 묶고 독자 효용·글의 질문·추천 여부·검증 필요성을 판단한다. 클릭률이나 조회수를 지어내지 않는다.
4. 추천 카드에서 같은 분석 결과를 사용해 초안을 작성한다. 본문 전체 확인, 담백한 문체, 이미지·표, 근거 있는 결론을 유지하면서 독자의 구체적인 상황과 읽을 이유를 강화한다.

## 반복 2: 실제 자료 QA와 보정
- 빈 분야에서 URL을 입력하지 않고 수집·추천까지 도달하는지 확인한다.
- 검색 실패·키 미설정·관련 자료 없음·모델 실패를 성공처럼 표시하지 않는다.
- 숨긴 자료와 이미 작성한 소재를 다시 추천하지 않는다. 특정 출처만 상위에 몰리지 않는지 확인한다.
- 실제 추천 상위 소재의 분야 적합성, 근거의 충분성, 독자에게 도움이 되는 질문을 검토한다.
- 실제 초안의 도입·용어 풀이·예시·결론을 읽고 제목의 약속이 충족되는지 검토한다. 실패하면 프롬프트와 후보 선정 기준을 수정한다.
- 반복 클릭·서버 재시작·예약 수집 후 자동 선별의 상태 전이를 검증한다.

## 완료 판단
자동 발견이 실제 외부 원문을 제공하고, 사용자가 대량 목록을 직접 선택하지 않고 추천을 통해 작성에 도달해야 한다. 테스트 통과만으로 유용성이 검증됐다고 하지 않는다. 실제 글과 추천 근거를 함께 확인하고 남은 한계를 기록한다. 실제 게시 성과 데이터가 없으므로 클릭률 개선이나 대중적 인기를 보장하지 않는다.

## 다음 반복의 후보
독자의 소재 보류·선호 피드백 반영, 검색 채널 확대, 게시 성과를 수동 기록해 추천 결과와 비교, 장문 콘텐츠의 독립적인 편집 평가. 실제 QA에서 드러난 문제를 우선한다.
