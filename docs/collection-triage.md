# 수집 소재 선별

## 사용 흐름

1. 편집 작업실의 **새 자료 수집 · 1차 분류**를 누른다. 예약/일반 수집 완료 시에도 1차 분류를 실행한다.
2. 미분류 자료는 관련 키워드, 최근성, 설명량, 실제 커뮤니티 관심 신호로 처리 순서를 정한다. 이 규칙 점수는 아직 내용 등급이 아니다.
3. 한 번에 최대 30건을 15건씩 묶어 제목과 설명 최대 900자를 AI에 전달한다. 한국어 제목·요약, T1/T2/T3, 판단 이유, 독자 효용, 글의 질문, 근거 한계를 저장한다.
4. 등급·AI 분류·한글 검색·정렬로 후보를 고른다. 전체 수집 자료를 페이지 단위로 조회하며 기존 500건/30일 후보 제한에 가려지지 않는다.
5. 최대 5건을 선택하여 **선택 자료 원문 집중 분석**을 실행한다. 원문을 확보하지 못한 자료는 제외 사유를 남기고 AI 집중 분석 입력에서 제외한다. 모두 실패하면 AI를 호출하지 않는다.
6. 집중 분석 결과에서 독자 질문·기획을 확인하고 기존 초안 작성/티스토리 저장으로 이어간다.

## 등급과 비용

- T1: 독자 효용과 구체적 근거가 있어 우선 검토. 75점 이상, 충분한 설명, LOW보다 높은 확신이 필요하다.
- T2: 유용할 가능성이 있지만 대상이 좁거나 확인할 내용이 있는 후보.
- T3: 관련성·효용·근거가 부족한 낮은 우선순위. 사용자가 직접 골라 집중 분석할 수도 있다.
- PENDING: 아직 한글 요약·내용 분류를 실행하지 않은 자료. 첫 화면에서 대기 수를 표시한다.
- 예상 조회수/클릭률을 생성하지 않는다. 알려지지 않은 관심 신호는 인기가 없다는 뜻이 아니다.
- 1차 요약은 발췌 기반이다. 집중 분석/글 작성은 확보한 원문 전체를 사용한다. 원문 추출 자체가 동적 로딩 내용을 보장하지는 않는다.
- 기존 자료는 배포만으로 무제한 AI 호출하지 않는다. 대기 자료를 15/30/60건씩 처리할 수 있다. 자동 수집도 30건까지만 호출한다.
- 캐시는 분야/독자 설정, 제목, 최초 수집 설명을 기준으로 한다. 집중 분석에서 원문을 저장해도 분류 캐시를 무효화하지 않는다. 독자 설정 변경 시 재분류 대기로 돌아간다.
- 실행별 실제 입력/출력 토큰을 저장한다. 잘못된 출력도 반환된 사용량은 기록한다. 실패 전 완료된 배치는 유지하고 자동 무한 재시도를 하지 않는다.
- 다른 AI 작업으로 분류를 시작할 수 없으면 자료를 대기 상태로 남긴다. 분류 실행 상태에서 재실행할 수 있다.

## 운영

Flyway V5는 topic_articles의 분류 결과, articles의 최초 설명/원문 상태, triage_runs의 진행·사용량 기록을 추가한다. 기존 글·분석·수집 데이터는 보존한다. 배포 전 기존 release.sh의 스키마 백업을 사용한다.

API는 기존 인증 아래 `/api/topics/{topic}/editorial/triage` GET/POST와 `/focus` POST다. 상세 분석/작성에 바로 연결되는 선택 ID는 분야 소속, 숨김/작성 상태, 중복, 개수, 분류 완료 여부를 검증한다.

검증: 한국어 검색/등급 필터, 분류 한도, 캐시 재사용, 잘못된 출처 ID 거부, 실패 사용량 기록, 수집 후 집중 분석 미실행, 원문 실패 시 AI 호출 차단을 자동 테스트한다.
